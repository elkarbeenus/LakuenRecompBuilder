LaküenRecomp v0.3.8 is one build for a PC, the Steam Deck and the Legion Go S. It brings fixes from Longshot, HeyListen and
Project ReLink for starts in SteamOS's Game Mode, memory on handhelds, render targets and a GPU freeze.

This release contains no game data, keys or executables: the AppImage is the builder, which builds the game on your PC from
your own copy. All of the recompilation work is NotRexed's and the Hookshot contributors'.

## Performance
- **Starts from SteamOS's Game Mode keep their prepared shaders** (Steam Deck, Legion Go S): Game Mode sets
  `RADV_FORCE_VRS_CONFIG_FILE` for everything it starts, and while that file exists RADV gives every graphics pipeline
  another key, so a start from Game Mode compiled the prepared pipelines all over again (about 20 a second on a Deck) where a
  start from the desktop loads them in seconds. The game now drops the variable at start and says so in its log; Steam's
  Half Rate Shading has no effect on it. `RX_VK_HALF_RATE_SHADING=1`: keeps it. From Longshot #900 (Zelda Ootr), via HeyListen.
- **Render targets reused, not made again:** the game's per-frame render targets that are done with go back to the pool
  every frame instead of every tenth, so the next frame takes them instead of making new ones (Longshot measured ~20 % of
  the render thread in making and destroying images). The pool's size per device stays as before.
  `RX_VK_DEAD_EVERY=10 RX_VK_DEAD_MIN_UNUSED=3`: as before. From Longshot #994 (SadTransGirl), via HeyListen.

## Memory
- **Less RAM on PCs and handhelds under 32 GB:** the game is told the memory it has mapped as used, as on the console. It had
  read about 9.6 GB free whatever it held and kept mapping pages it never gave back: up to 1.1 GB of RAM saved in busy areas.
  On under 32 GB of RAM only (the Steam Deck, the Legion Go S, 16 GB PCs); `HOS_MEMINFO_OLD=0` / `1` turns it on / off on any
  PC. From Longshot #324, via HeyListen.

## Stability
- **No freeze from a pipeline built for another program:** two program objects can share a pipeline's key; with every shader
  prepared at start (as here), a draw could run one program's shaders under the other's data, and the GPU never finished
  (a freeze near water in Project ReLink's reports). Each program object now gets its own pipeline.
  `RX_VK_PIPE_BY_PROGRAM=0`: as before. From Project ReLink (pixl27).

## For testing
- `RX_VK_READBACK_STRICT=1040,c0`: only the light meter's readbacks wait for their write-back, against the light pulsing on
  RADV (HeyListen's default there; off here, as the frame rate comes first).

## Kept
- The PC profile, Fog boxes (Off), Fog density and Brightness (100 %), the in-game diagnosis, the master log after every run,
  Update inside the builder.

## Known issues
- Some places look too bright in a white haze (a fairy's fountain, the Zora's domain); the cause is open.
- Busy areas (the open field) drop below 30 fps now and then on handhelds.
